# VoiceStudio 第二轮产品修复与控件取舍

## 训练为什么停在 47%

旧流程在自动识别文字之后强制停到 `review_required`。校对入口挂在右栏底部的主按钮上，右栏又没有合理滚动布局，长素材列表下用户看不到入口；任务浮层还保留着上一阶段的进度。这是工作流和界面共同造成的问题。

文字声音训练需要音频与文字配对，因此有自动转写和可选校对；这不等于每次训练都必须人工点击通过。GPT-SoVITS 上游也将切片、ASR、标注作为素材准备工具。[上游说明](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/README.md)

现在默认自动筛选无质量异常、非空文本的片段并继续训练；自动接受与人工确认分别记录。只有合格时长不足 60 秒、缺少 5–10 秒参考片段等实际条件不满足时才暂停，显示具体原因。人工校对是可选设置，入口固定在页面顶部。

已有停在校对阶段的任务不必重新导入：顶部“自动筛选并继续训练”可以使用已有草稿继续。校对按钮可以直接打开文字编辑。选择同时训练文字与歌唱能力时，文字模型完成后继续提交歌唱模型训练。

## 卡顿与闪窗根因

1. 每条工作日志触发完整页面状态刷新，重画列表、控件并重复读取工程。
2. 翻唱状态查询同步读取 UVR5、约 953 MB 的 RoFormer 模型并校验全部内容；本来只是点按钮或刷新状态，却在读大文件。
3. 素材准备结果在 GUI 线程里逐段扫描音频、计算质量；数据冻结也同步复制文件。
4. 部分 FFmpeg、ffprobe、训练子进程缺少 Windows 隐藏控制台选项，逐段处理时产生连续闪窗。

已将日志与数据刷新分开、合并完成事件刷新，训练进度变化不再重建素材列表；耗时的扫描、复制、冻结放到后台线程，后台结果再回到界面线程。页面只检查模型是否已安装，真正使用模型前仍保留工作进程内的完整校验。相关媒体和训练子进程统一静默启动。关闭任务浮层后，同一任务的进度更新不会把它重新弹出。

素材概况不再把时长比例包装成“质量 100 分”，也不再将文件数量标成信噪比、将时长标成混响指标。

## 控件逐项处理

| 控件 | 本轮处理 | 理由/边界 |
|---|---|---|
| 翻唱效果预设 | 接入“均衡 / 音色优先 / 辅音优先” | 实际修改 Index Rate 与 Protect；是参数组合，不保证特定音质 |
| RVC 高级参数 | 接入 Index Rate、Protect；显示实际 F0 为 RMVPE | 当前固定引擎只支持 RMVPE/auto，不展示无效的 CREPE、Harvest |
| RMS Mix | 暂不恢复 | 当前桥接固定该值；需要补齐参数、缓存及验证后再开放 |
| 音色强度、细节保留 | 不另加两套含糊滑块 | 使用上述实际参数，避免重复控制和误导命名 |
| Take 版本条 | 暂不恢复，建议下一阶段优先实现 | 需要版本资产、参数快照、切换和清理逻辑，不能只做一条版本按钮 |
| A/B 对比 | 接入原曲 A / 最终成品 B，同位置切换 | 不冒充两个 Take 版本之间的比较 |
| 20 秒选区试听 | 接入从当前播放位置试听 20 秒 | 可先点波形定位；播放已有音轨，自动停止 |
| 局部重新渲染 | 暂不恢复 | 当前推理与缓存以完整歌曲为单位，需要专门的区间渲染契约 |
| 缺失时自动分离 | 暂不新增开关 | 保留现有分离步骤；建议未来整合成完整的一键翻唱任务，避免空开关 |
| 自动音高校正 | 改为高级设置内的“音高平滑” | 当前实现减少抖动，不是按调式修正跑调 |
| TTS 情绪按钮组、音高滑块 | 暂不恢复 | 当前固定引擎没有对应的可用控制契约；情绪更适合用参考音频表达 |
| TTS 输出开关卡片 | 暂不恢复 | 当前输出链路未实现这些独立开关；保留已有生成与导出入口 |
| 训练质量下拉 | 改为真实“训练时长” | 快速 4/5、标准 8/15、加长 12/20 轮（SoVITS/GPT）；更多轮数不保证更好 |
| 分离“极致·多轨” | 暂不恢复 | 当前两种分离模型只产出人声和伴奏，不支持鼓/贝斯等多轨 |
| FLAC / M4A 导出 | 接入 | 包含编码、输出验证、格式选择；M4A 使用 AAC |
| 批量队列等未接入动作 | 明确提示“该功能尚未接入新界面” | 不返回演示成功 |

RVC 参数命名参考上游文档，但界面开放范围以本项目固定版本的实际实现为准，不通过升级模型或增加大型下载来制造表面支持。[RVC 官方 CLI 文档](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/blob/main/docs/en/cli.md)

## 产品改进建议（尚未全部实现）

按收益和依赖排序，建议下一阶段集中做以下几项，而不是继续堆控件：

1. **完成“导入—训练—试听”的闭环。** 训练完成后直接给两段标准试听，显示文字声音和歌唱声音分别是否可用；用户可以保留旧声音或启用新版本。
2. **持久任务中心。** 显示当前阶段、已用时间、最后一次活动、暂停原因和明确的继续按钮；日志折叠到详情；支持进程重启后恢复任务。后台模式只在需要处理和任务完成时提醒。
3. **训练前给素材结论，不给虚构评分。** 展示有效片段时长、空文本、过短、削波等实际数量，并允许只试听被排除的片段。给出“还差多少可用素材”的明确行动建议。
4. **优先保存每次成品和参数版本。** Take 记录、参数差异、同段落 A/B、恢复旧版本比新增情绪按钮更有价值，也能减少反复整首生成。
5. **把一键翻唱做成一个可恢复任务。** 自动完成缺失分离、转换、混音，在确认声音和参数后连续执行；内部阶段不要变成需要用户逐个点击的按钮。
6. **设交互性能门槛。** 普通点击应立即反馈，状态接口不能读取大模型；大列表按需更新。加入日志洪峰、长素材列表、低分辨率下的界面回归，持续防止这次问题复发。

这些优先级是基于本项目已发现的问题与现有引擎能力作出的产品判断，不是音质效果保证。
