# VoiceStudio 功能审计 — 2026-09-09

结论：当前界面把 UI 原型的演示脚本与真实服务适配器一起运行，存在按钮只改外观、操作接错、事件丢失和多份选中状态不一致。用户反馈有实质依据。应先修复页面接入与状态流，不能靠调整界面样式或重新安装模型解决这些问题。

本轮按“审计项目”交付复现工具、证据与修复顺序，**未修改业务代码、未重打包 EXE，以下问题仍存在**。

## 入口与验证范围

- 根目录 `VoiceStudio-一键启动.exe` 的对应源码 `quick_launcher.py:20` 优先启动 `dist/LocalVoiceStudio/LocalVoiceStudio.exe`。
- 实测了该目标 EXE，使用临时数据目录、临时项目与合成的 1 秒、8 kHz、单声道静音 WAV。未改动用户项目、音频、模型或数据库，未执行真实训练、推理、分离或模型安装。
- 打包目录中的 `index.html`、`studio-bridge.js`、`studio-pages.js` 与源码对应文件 SHA-256 逐一相同。
- 打包程序的桥接连接正常，`bridgeError` 为空。不能把本次问题归因于“启动了原型 HTML”或“打包程序完全没有连接 Python”。
- 原型 `VoiceStudio_Full_UI_Prototype_v4.html` 保持原样。它适合作为视觉参考，其假数据、模拟进度与演示事件不应成为产品功能的默认实现。
- 没有用户实际导入失败的音频文件。本轮确认的是下面这些可独立复现的问题，不能据此断言所有音频格式、编码和系统文件选择对话框均正常。

证据：`source-evidence.json`、`packaged-evidence.json`、`packaged-import.png`。其中源码探针替换原生选择器，让它返回临时 WAV；打包探针通过真实桥接传入应用管理目录内的 WAV 路径，未操作原生选择器。

## 已确认问题

P1：主流程阻塞、操作对象错误或关键能力名存实亡；P2：具体入口/控件失效或具有误导性。

### A01 · P1 · 首次导入成功后，翻唱主按钮仍认为没有歌曲

**复现：** 空项目 → 导入 WAV → 左侧出现歌曲并选中 → 点击“一键生成翻唱歌曲”。提示“请先导入或选择一首歌”。源码和打包 EXE 均已复现。

**证据：** 打包返回 `ok: true`，歌曲数为 1，`__vsBridge.song.id` 非空，`VS_PAGES.cover.songId` 却为 `""`。

**原因：** `studio-bridge.js:706` 的 `applyState()` 更新歌曲列表与 `S.song`，未同步 `studio-pages.js:128` 的独立 `cover.songId`。后者主要在首次安装页面和点击歌曲行时更新；空项目启动时没有可初始化的歌曲。

**修复：** 用稳定歌曲 ID 建立唯一选中状态；导入、列表刷新、项目切换都同步状态和操作按钮，不能要求用户再点一次已选中的歌曲。

**临时绕行：** 成功导入后，再点一次左侧歌曲行。此方法仅绕过首次状态同步问题；不表示后续流程已通过验证。

### A02 · P1 · 同名歌曲会操作错误的工程

**复现：** 导入两个同名歌曲工程 → 点击列表第二个 → 页面选中 ID 与翻唱操作 ID 不同。已在真实 QtWebEngine 页面复现。

**原因：** `studio-pages.js:161` 的 `syncFromLibrary()` 读取可见标题，再用 `.find(item => item.title === title.textContent)` 找第一首同名歌曲。适配层的行点击却按对象正确选中了第二首。

**影响：** 分离、歌词识别、转换、混音等使用 `cover.songId` 的命令可能指向另一个工程。

**修复：** 行元素保存 `data-cover-id`，操作直接使用当前选中 ID；增加同名、筛选后选择和跨项目切换测试。

### A03 · P1 · 训练、声音变更与安装事件被桥接适配器丢弃

**复现：** 向真实页面发送 `training.scanning`、`training.error`、`voices.changed`、`engine.install.started/log/done` 以及 `job.progress`。页面模块只收到 `job.progress`，安装进度窗口没有出现。

**原因：** `studio-bridge.js:870` 只转发 `job.*`；`studio-pages.js:995` 明明实现了 `training.*`、`voices.changed`、`engine.*` 的接收逻辑，却无法收到通知。

**影响：** 素材扫描完成后训练状态不自动更新、异步导入错误不可见、安装开始/日志/完成缺少反馈，表现为点击后不动或一直等待。

**修复：** 明确并统一页面事件路由；对成功、失败、取消、扫描完成和安装完成做真实 Signal → QWebChannel → DOM 测试。

### A04 · P1 · 训练片段审核弹窗为空，也不能校正识别文字

**复现：** 以正常审核状态结构提供一个异常片段，打开“确认训练片段”：弹窗存在，但片段行数为 0，编辑控件数为 0。

**原因：** `studio-pages.js:761` 创建 `#trainDraftPanel` 时没有在 `onReady` 中调用 `paintDraft()`；`paintDraft()` 在此前页面绘制时调用，彼时容器不存在。即使手动重绘，`studio-pages.js:705` 也仅生成截断文字和纳入/排除按钮，没有文字编辑器；`bridge.py:493` 的确认入口只接收纳入/排除 ID，不接收文字修正。

**影响：** 无法完成 UI 声称支持的人工检查与转写校对。不能依赖偶然到来的刷新事件填充弹窗。

**修复：** 在弹窗准备后绘制片段，接入现有草稿编辑与持久化能力，再按保存后的数据确认训练。

### A05 · P1 · 多轨静音/独奏与实时混音试听没有接入

**复现：** 检查真实页面 10 个 M/S 按钮，处理函数全部仅为 `classList.toggle('active')`。

**原因：** 原型 `index.html:120` 的演示处理被保留；`studio-bridge.js:620` 只创建一个 HTML Audio 对象，未把轨道按钮连接到项目已有的多源试听控制器。混音滑块数值在 `studio-pages.js:295` 的最终渲染中读取，但没有对应的多轨实时试听更新。

**影响：** 按钮会亮，声音却不会按 Mute/Solo 或多轨混音改变。“生成最终混音会读取增益”和“拖动滑块能实时听见效果”是两项不同能力，后者未接入。

**修复：** 复用现有 Preview Controller 的同步播放、Seek、Mute/Solo、增益能力，验证实际输出/播放状态；未接入期间禁用控件并说明状态。

### A06 · P2 · 导入入口仍使用示例文件名弹窗，目标选择无效

**复现：** 点击“导入歌曲到工程”，首先出现“原型中会模拟…”和“示例文件名”的弹窗；此时原生文件选择器调用次数为 0。继续点击弹窗“导入”，才调用真实选择器。

**原因：** `index.html:101/111` 保留原型导入弹窗；`studio-bridge.js:771` 只替换确认按钮，固定调用 `song.import`，未读取 `importTarget` 或 `importName`。因此用户选择“训练声音素材/音频分离工具”也不会按该选择导入。页面没有注册音频 `dragover/drop` 导入逻辑，不能提供文字宣称的拖入能力。

**修复：** 歌曲导入直接打开真实文件选择器；通用导入按实际目标调用对应服务。不要要求用户填写假文件名。拖放需通过可信的桌面文件选择/授权通道实现。

### A07 · P2 · “导入 LRC”接成了自动识别歌词

**证据：** `studio-pages.js:140` 将 `.lyrics .mini` 绑定到 `transcribe()`；`:326` 调用 `cover.lyrics`，`bridge.py:429` 最终执行本地语音识别，没有选择或解析用户 LRC 文件。原型的“已载入示例 LRC”提示监听器还存在。

**影响：** 用户想导入已有歌词，却进入识别流程，且可能因模型未安装而失败。

**修复：** 分别提供“导入 LRC”和“自动识别”，接入项目已有歌词解析能力，不混用入口。

### A08 · P2 · 去混响开关始终无法把清理参数传给转换

**证据：** `studio-pages.js:285` 查找 `#dereverbToggle`，真实页面匹配数为 0；因此转换请求中的 `cleanup` 始终为 `null`。界面仍显示可切换的“去混响”。

**修复：** 为真实开关建立稳定标识和参数绑定，测试开/关两种情况下的 Worker 命令，而不是只验证开关样式。

### A09 · P2 · TTS 声音搜索被清空，刷新还会重置已选声音

**复现：** 页面加载后的搜索处理函数是空实现；选择第二个声音后执行正常 `app.refresh`，当前选中 ID 变回第一个声音。已复现。

**原因：** `studio-pages.js:379` 覆盖了 `studio-bridge.js:758` 已经正确绑定的搜索处理；`:237` 每次重建列表都让 `index === 0` 激活。导航、任务事件等都会触发全局刷新。

**修复：** 保留搜索绑定，用独立的 TTS 查询状态与声音 ID 渲染列表，刷新后保持用户选择。

### A10 · P2 · 导入未完成音频分析，页面还显示假波形与假状态

**证据：** 1 秒、8 kHz、单声道静音 WAV 导入后，歌曲元数据时长为“—”；打包截图仍显示 `44.1 kHz / Stereo`、长达 `04:29` 的标尺、多条波形、未存在的已训练声音和“缓存命中 · 约 48 秒”。静音源文件不应产生这些多轨波形。

**原因：** `services/cover.py:57` 仅创建工程、复制和保存，未调用已有分析服务。`cover/project.py:372` 的复制逻辑不填充时长/采样信息；原型 `index.html:122` 的 `drawCanvas()` 用正弦函数绘制演示波形。适配器没有完整接管这些区域。

**影响：** UI 不能作为素材分析、分离结果、目标模型可用性或缓存状态的可信依据；后端存在真实波形/分析实现并不代表当前页面已经使用。

**修复：** 接入元数据和真实波形分析，显示空轨/未分析状态；完全清除运行页面里的演示数据与任务模拟器。

### A11 · P2 · 训练素材试听缺少文件路径

**代码核查：** `services/training.py:63` 的素材状态包含 `exists/name/id` 等，但没有 `path`；`studio-pages.js:651` 却调用 `S.playFile(asset.path, asset.name)`。`:610` 附近的 `fileUrl()` 会把 `undefined` 转成错误文件 URL。

**影响：** 由训练模块 `paint()` 渲染出的素材试听按钮无法指向真实素材文件。适配层和训练模块都在重画素材列表，不能把某次刷新产生的另一种行行为当作此问题已解决。

**修复：** 定义唯一素材显示契约，返回受控的项目素材路径/资源 ID，并测试试听地址实际存在。

### A12 · P2 · 任务中心“取消”只提示去不存在的经典界面

**代码核查：** `studio-bridge.js:371` 创建的取消按钮只显示“运行中的任务请先在经典界面取消”；`:387` 仅调用 toast。桥接未知操作提示还建议 `--ui-qt`，但 `app.py:33` 附近的入口始终创建 WebStudioWindow，没有此切换分支。

**影响：** 任务中心取消按钮不发送任何取消命令，给出的绕行路径也不可用。页面任务浮窗中存在其他取消路径，不能证明任务中心按钮可用。

**修复：** 按任务类型与 request_id 路由到现有取消服务，并更新真实取消状态；删除失效指引。

## 建议修复顺序与验收

1. **恢复基本入口与正确操作对象：** A01/A02/A03/A06。空项目从真实选择器导入后立即可继续；同名歌曲不串工程；训练/安装成功和错误消息都可见。
2. **让界面描述符合真实能力：** A05/A07/A08/A10/A12。清除演示行为，接入实际已有服务；未接入的功能应禁用并解释，不返回假的成功提示。
3. **完成训练与 TTS 的实际使用闭环：** A04/A09/A11。素材试听、异常片段校对、保存、确认训练、声音选择与生成均能完成。
4. **最后重新打包并沿用户入口验收：** 不只验证源码。覆盖 WAV/MP3/FLAC、中文和空格路径、取消选文件、空项目、同名歌曲、刷新、项目切换与重启恢复。选择一个有授权的最小素材，再单独验证真实 GPU 工作流。

界面外观以 v4 原型为参考；修复应复用现有服务和控制器，先统一状态与事件所有权，不需要重写整个后端。
