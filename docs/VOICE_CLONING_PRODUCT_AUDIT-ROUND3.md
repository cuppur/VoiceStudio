# VoiceStudio 声音克隆产品审计（第三轮）

审计日期：2026-09-25。目标是检查本机实际运行能力与用户界面动作是否对应真实功能。这里的“已验证”指本地运行真实模型或媒体工具得到文件并完成基本完整性校验；单元测试通过不等同于音质评估。

## 结论

项目已具备一套真实可用的本地声音克隆与 AI 翻唱主链：导入授权素材、训练数据准备、GPT-SoVITS 文字合成、RVC 歌唱转换、双轨分离、混音、导出和任务续跑。它目前更接近“本地声音创作工坊”，还不是完整 DAW 或可无条件保证效果的成品级克隆平台。

本机环境探测为 GPT-SoVITS、UVR5、RoFormer 和 RVC 均就绪；现有档案共 6 个，包含 2 个歌唱模型版本，其中 1 个已通过验证并启用。实际合成、分离、RVC 转换和混音已在临时工程完成。**这轮没有对新的声音档案跑完 SoVITS/GPT 或 RVC 全量微调**：之前卡住的是训练进程创建后的 NumPy/Torch 初始化死锁，现已修复并经过隔离验证，但训练轮次和新模型质量仍应在下一次真实训练中观察，不能用短音频推断。

## 核心功能与边界

| 能力 | 状态 | 本轮审计结论 |
|---|---|---|
| 导入、检查、管理声音/歌曲素材 | 可用 | 本地导入与删除有真实服务；歌曲删除移入工程回收目录，不删外部原件。训练页在耗时扫描期间异步响应。 |
| GPT-SoVITS 文字声音 | 可用 | 本机模型可加载并真实生成非静音 WAV；旧档案安全加载路径也实际走过 Worker 的信任迁移函数。 |
| 训练数据自动准备 | 可用 | 隔离项目上真实运行素材归一化、切分和本地 ASR，完成 1 个片段与 1 条转写。自动筛选、可选校对、失败恢复与状态持久化已有实现；全量微调尚未运行。 |
| 训练后试听和版本管理 | 已接入 | GPT 与 SoVITS 能力状态分开展示；新模型先试听/验证，再选择启用，可回到既有版本。质量下拉表达训练时长，不承诺效果等级。 |
| RVC 歌唱声音训练/转换 | 组件可用 | RVC 隔离环境可用；本机已有 1 个已验证活动模型。本轮以该模型实际转换测试音频。新模型的全量训练尚未测时长。 |
| 歌曲人声/伴奏分离 | 可用 | UVR5 与 RoFormer 两个模型均已就绪；实际短音频分离得到有效双轨。仅输出人声与伴奏，不支持鼓、贝斯等多轨。 |
| 一键翻唱 | 可用，依赖已验证歌唱模型 | 后台按“分离 → RVC 转换 → 混音”顺序执行，持久化每阶段结果，失败后可从未完成阶段继续。 |
| Take、A/B、恢复旧成品 | 已接入 | 保存混音版本和参数快照；可切换启用、比较同一播放位置并恢复历史成品。 |
| 歌词、调音、混音和导出 | 部分可用 | 手动 LRC、自动识别、RMVPE 音高建议、音轨混音与 WAV/MP3/FLAC/M4A 导出有后端；当前自动音高功能是“平滑”，不是按调式纠正跑调。 |
| 实时/流式生成、批量处理、局部重新渲染、多轨拆分 | 尚未接入 | 不应显示为已完成动作；新界面应明确提示尚未接入。 |

## 真实性能诊断

原先“训练中”并非 GPU 正在低效训练：采样时没有 Python GPU 子进程或训练运行目录；Worker 的工作线程停在第一次导入 NumPy 的原生扩展，界面仍保留运行状态。用户截图里的 CPU/GPU 百分比是整机瞬时统计，无法说明进程级负载。当前已把 NumPy 初始化移到 Worker 主线程收命令之前，避免 Windows 下子线程与 Torch 首次导入互相卡住；同时修复了产品任务 ID 被覆盖、导致任务中心永久显示排队的问题。

分离模型成本差异明显：先前隔离测试中，UVR5 处理 8 秒音频约 4.83 秒，RoFormer 约 70.39 秒。RoFormer 默认不再被状态刷新反复完整校验，一键翻唱默认优先用 UVR5；需要更细人声时再选 RoFormer。短任务、模型启动和预处理会造成 GPU 利用率跳动，只有在确认训练进程已启动后，才能根据阶段耗时、GPU 进程显存和实际轮次判断是否还存在吞吐瓶颈。

## 同类开源项目可吸收点

| 项目 | 上游已有做法 | 对 VoiceStudio 的建议 |
|---|---|---|
| [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) | 同时支持短参考音频零样本 TTS、少样本微调、跨语言生成和数据集切分/ASR 辅助。 | 将“快速试听”和“微调训练”明确分开；训练前展示可用时长和片段质量，让短素材先生成试听而不误导用户必须立即训练。 |
| [RVC WebUI](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI) | 将数据预处理、F0/特征提取、模型训练和 index 构建呈现为清楚阶段；推理参数及缺失 index 的行为有明确规则。 | 保留本项目已接入的 Index Rate、Protect、RMVPE；后续要开放 RMS Mix 或其他 F0 算法，必须连同后端、缓存键、验证和输出说明一起完成。 |
| [F5-TTS](https://github.com/SWivid/F5-TTS) | 长文本分块生成、多说话人/风格示例，且明确给出参考音频长度与切句建议。 | 先吸收长文本分段、每段试听和失败段续跑的交互，不立即引入一套新的大模型依赖。 |
| [CosyVoice](https://github.com/FunAudioLLM/CosyVoice) | 覆盖多语言/方言、指令控制和文本入流/音频出流；提供推理、训练和部署链路。 | 可作为未来独立 TTS 引擎评估对象；先做模型体积、Windows/CUDA 兼容、显存共存和许可审计，再决定是否增加可选下载。 |

## 后续优先级

1. 在真实的新训练中记录“数据准备、SoVITS 轮次、GPT 轮次、模型验证”的分段耗时和 GPU 进程级利用率；训练未启动时不要显示为训练中。支持暂停/恢复的前提是保存训练运行状态，不能只恢复界面进度。
2. 在不增加模型依赖的情况下，完成长文本分块生成、当前句/失败句定位与单句重试。将模型冷启动时间与真正推理时间分开展示。
3. 首次使用训练页解释素材时长与训练用途：快速试听可用短参考音频，微调建议更长且干净的素材；将质量诊断转成“可行动建议”，不编造一个综合分数。
4. 导出页增加目标响度、峰值/削波检查和导出后试听；已有格式选项继续按实际编码结果校验。
5. 继续保持未接入控件显式报状态；不要加入只有视觉效果的情绪、局部渲染、多轨或参数滑块。
